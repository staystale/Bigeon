Goal: `bigeon accept NNN`, one safe command for the foreman to move a reviewed worker branch onto main.
Steps:
1. git fetch origin. git log -1 --format=%h origin/main must print 592de0d or newer; if not, stop and report it.
2. git checkout -b worker/029 origin/main
3. src/lib.ts: export function mainRef(projectDir, remote): string | null, the main-branch lookup now inside baseLine
   (refs/remotes/<remote>/HEAD, else <remote>/main, else null). Make baseLine in src/worker.ts use it. Do not duplicate it.
4. New src/accept.ts with:
   a. export function githubRepo(url: string): { owner: string; repo: string } | null for https://github.com/o/r(.git)
      and git@github.com:o/r(.git); anything else null.
   b. export function summarizeChecks(json: unknown): 'success' | 'failure' | 'pending' | 'none' from a GitHub
      check-runs response ({ check_runs: [{ status, conclusion }] }): none if empty or unreadable, pending if any
      status is not 'completed', failure if any conclusion is not success/skipped/neutral, else success.
   c. export async function accept(projectDir, config, id, options: { dryRun?: boolean; timeoutMinutes?: number; log }):
      Promise<number>, in this order, stopping at the first problem:
      - git fetch --quiet <remote> (failure -> log, return 3).
      - Branch <remote>/worker/<id> must exist, else `no branch worker/<id>`, return 1.
      - The result note results/<id>.md (read it through the comms worktree, pulled) must contain `Status: PASS`,
        else `result <id> is not PASS`, return 1.
      - main = mainRef(...). main must be an ancestor of the branch (git merge-base --is-ancestor main branch),
        else `worker/<id> is behind <main>: send the task again from the current main`, return 1.
      - Log the short sha and `git diff --stat main branch`.
      - CI: if githubRepo(remote url) is null, log `not a GitHub remote, skipping the CI check`. Otherwise poll
        https://api.github.com/repos/<o>/<r>/commits/<sha>/check-runs with fetch (header Authorization: Bearer
        $GITHUB_TOKEN only when that env var is set) every 15 s until summarizeChecks is not pending, up to
        timeoutMinutes (default 15). failure -> `CI failed for <sha>`, return 1. Still pending -> return 5.
        none or a fetch/HTTP error -> log `could not read CI results, the main branch rules still apply` and go on.
      - dryRun: log `dry run: would push <sha> to <main>`, return 0.
      - git push <remote> <sha>:<main branch name> (no force). Failure -> log git's error, return 1. Success -> log
        `accepted <id>: <main> is now <sha>`, return 0.
5. bin/bigeon.ts: `bigeon accept NNN [--dry-run] [--timeout MINUTES]` calling accept; add it to the help text with the exit codes.
6. Tests, new test/accept.test.ts (reuse test/helpers.ts; local bare remote, so the CI step is skipped):
   a. githubRepo and summarizeChecks unit tests (each case in 4a/4b).
   b. PASS result and branch on top of main -> exit 0, remote main now equals the branch sha.
   c. FAIL result -> exit 1, main unchanged.
   d. branch made from an older main (push another commit to main first) -> exit 1, output matches /is behind/.
   e. --dry-run -> exit 0, output matches /dry run/, main unchanged.
   f. no such branch -> exit 1.
