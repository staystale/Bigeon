Goal: worker safety limits, so a task can never loop forever or run twice.
Steps:
1. git fetch origin, then: git checkout -b worker/015 origin/main
2. src/worker.ts:
   a. Interruption limit. .bigeon/in-progress.json becomes {"id": "<id>", "attempts": N, "agentPid": number | null}.
      When a task starts and the marker has the same id, attempts = previous + 1, else 1. If attempts > config.maxTries,
      do not run the agent: send a FAIL result whose Errors line is `interrupted <attempts-1> times, giving up`
      (use resultNoteText with a CheckResult { status: 'FAIL', exitCode: null, timedOut: false,
      errors: ['interrupted N times, giving up'], hiddenLineCount: 0 }), mark the task seen, delete the marker, continue.
   b. Leftover agent. Store the agent's pid in the marker as soon as it is spawned (runAgent gets an onSpawn(pid) callback).
      When a task starts and the marker has an agentPid, stop that process tree first with the same killTree logic
      (Windows taskkill /T /F; otherwise process.kill(-pid)), ignoring errors if it is already gone,
      and log `[bigeon] stopped leftover agent <pid> from an interrupted run`.
   c. Stash note. If leftovers were stashed for this task, add `Stashed: leftovers from the interrupted run (git stash list)`
      to the result note (add an optional extra-lines parameter to resultNoteText; keep existing callers working).
3. Single loop lock. At the start of runWorker, create .bigeon/worker.lock containing {"pid": process.pid}.
   If it exists and that pid is still running (process.kill(pid, 0) succeeds), throw an Error:
   `another bigeon worker is already running in this folder (pid <pid>)`. If the pid is not running, take the lock over
   and log `[bigeon] took over a stale lock`. Remove the lock when runWorker returns or throws (try/finally), and on
   SIGINT/SIGTERM (process.once handlers that remove it, then exit with code 130).
4. Tests, add to test/recover.test.ts (reuse helpers, add helpers to test/helpers.ts if needed, do not duplicate code):

      hanging agent (existing crashWorker), then run worker --once with any agent. Assert foreman result has
      Status: FAIL and matches /interrupted 2 times, giving up/, and the agent did not run on that last start.
   b. 'a second worker in the same folder refuses to start': write .bigeon/worker.lock with {"pid": process.pid}
      (the test runner itself, which is running). worker --once must exit non-zero with stderr matching /already running/.
   c. 'a stale lock is taken over': lock with pid 999999 (not running). worker --once with a quick agent passes and
      stdout matches /took over a stale lock/.
   d. 'a leftover agent from a crash is stopped on restart': the crashing agent spawns a grandchild that hangs and writes
      grandchild.pid, then writes started.txt. After crashWorker, do NOT kill that grandchild in the test. Run worker --once
      again with a quick agent; assert stdout matches /stopped leftover agent/ and the grandchild pid is gone within 5 s
      (same polling as the timeout test; kill it and fail if still running).
