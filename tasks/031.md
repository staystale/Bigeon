Goal: a FAIL result's Errors must show the failure, not the first lines of output. Today runCheck keeps the first
errorLines lines, which are usually passing tests (result 019 showed 14 passing lines and hid the failure).

3. src/lib.ts: add export function pickErrorLines(allLines: string[], count: number): { shown: string[]; hidden: number }.
   - Strong markers: /✖|^\s*not ok\b|\bFAIL\b|Error:|AssertionError|Traceback|panic:/
   - Weak markers: /error|fail/i, but not lines matching /\b(fail|failed|failures|errors?)\s*[:=]?\s*0\b/i
     (so "fail 0" or "errors: 0" summary lines do not count).
   - Start = index of the first strong match, else the first weak match. If found, start the window 2 lines before it
     (not below 0) and take count lines from there. If nothing matches, take the LAST count lines.
   - hidden = allLines.length - shown.length.
   runCheck uses it instead of slice(0, errorLines). formatCheck's "... N more lines hidden" stays.
4. Tests in a test file that already tests runCheck/formatCheck, or a new test/lib.test.ts:

      "✖ broken test" and the AssertionError line; shown[0] is "✔ test 29 passes" (2 lines of context).
   b. Only weak markers: 10 plain lines then "something failed here" -> that line is shown.
   c. "ℹ pass 5" / "ℹ fail 0" and plain lines, no markers otherwise -> the LAST count lines are shown.
   d. Fewer lines than count -> all shown, hidden 0.
