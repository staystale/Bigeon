Goal: make the recovery tests reliable and check existing results before skipping a task.
The test "leftovers from an interrupted run are cleaned before the retry" fails on slower machines: crashWorker kills the
worker after a fixed 1000 ms, sometimes before the task has even started, so there is nothing to recover. It also kills only
the worker process, so the hanging fake agent keeps running in the background.
Steps:
1. git fetch origin, then: git checkout -b worker/014 origin/worker/013
2. test/helpers.ts: add export function killTree(pid: number): void (Windows: taskkill /pid <pid> /T /F with stdio ignore;
   otherwise process.kill(-pid, 'SIGKILL') in try/catch, falling back to process.kill(pid, 'SIGKILL')).
3. test/recover.test.ts, crashWorker: replace the fixed timeout. Start the worker with spawn (not spawnSync), with
   detached: process.platform !== 'win32' and stdio 'ignore'. Every crashing agent must write started.txt as its LAST
   step before hanging. Poll every 100 ms, for up to 20 seconds, until started.txt exists in the worker clone (fail the test
   if it never appears). Then killTree(child.pid) and wait for the child's 'exit' event. Make crashWorker async and await it.
4. src/worker.ts, the "already has a result" skip: only skip when that results/<id>.md contains a line matching
   /^Status: (PASS|FAIL)$/m. Log `[bigeon] task <id> already has a <PASS|FAIL> result, skipping`.
   Otherwise (empty or no Status line) log `[bigeon] task <id> has an incomplete result, doing it again` and do the task.
5. test/recover.test.ts: update test (c)'s regex to /already has a PASS result/. Add test (e)
   'a task with an incomplete result is done again': send task 001, then bigeon send result 001 --text 'half written'.
   The agent writes ran.txt. Assert ran.txt exists and stdout matches /incomplete result/.
